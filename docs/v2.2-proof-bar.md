# v2.2.0 live proof bar

[RAI-63](https://linear.app/raitox/issue/RAI-63/v220-proof-bar-same-org-all-harnesses-cross-org-97)
tracks the original v2.2.0 release gates. The maintainer waived these live-proof
gates for this release; that waiver is not evidence of acceptance. Live
same-org, cross-org, and external relay-binding evidence is NOT recorded for
v2.2.0. Merges and passing CI do not change that. The checks below define the
original acceptance criteria and do not certify completion. Cross-owner grant
CLI/MCP surfaces were removed in v2.2.0, so cross-org delivery is not available
in this release. Announcement also requires Wright's approval.

## Original proof-bar gates (not completed)

| Gate | Original live acceptance check |
| --- | --- |
| Same-org, all harnesses | Every applicable harness can send to and receive from every other applicable harness. Include `claude`, `codex`, `grok-bot`, `openai-dot`, and `hermes`, plus other harnesses in the trial. Record any inapplicable harness and the reason explicitly. |
| Cross-org messaging | Original gate: both org admins explicitly opt in to the named agents, then prove a message, recipient consumption, correlated reply, and revocation. The cross-owner grant CLI/MCP surfaces were removed; this gate was not run and is not supported by this release. |
| External relay binding, [#97](https://github.com/raitoxlol/everett/pull/97) | Exercise the bound registration path for both `grok-bot` and `openai-dot` against a real pinned peer. Capture `transport: "relay"` and the relay `message_id`, then prove remote MCP inbox consumption and a correlated reply. A direct peer send alone does not prove the bound registration path. |

For each run, record the candidate revision, timestamp, harness pair and
direction, authorized org scope, message ID, recipient tool result, and reply.
Keep credentials and webhook URLs out of evidence. Queue receipts and HTTP 200
alone do not prove consumption. Record failures and untested pairs as pending.

## Remaining evidence under RAI-63

These checks were not completed for v2.2.0. Attach any future evidence to RAI-63
before describing a gate as proven.

- [ ] Complete the same-org directed harness matrix with real inbox pickup and
  correlated replies, including a bound Codex MCP caller.
- [ ] If cross-owner grant support returns, run the opt-in trial with both
  admins, including the reply and revocation checks.
- [ ] With implementation PR #97 and receiver-resilience PRs #109/#110 merged,
  prove both external bindings through the relay and attach their receipts,
  consumption, and replies. Live proof remains unrecorded.

For external agents, use the [webhook wake and MCP polling path](grok-bot.md#wake-a-grok-bot-with-a-webhook-routine).
The [Grok Bot 0.77 reachability note](grok-bot.md#grok-bot-077-reachability)
does not provide private-MCP proof or waive any gate.
